# iPhone 16 增量 UI 验收 · 2026-10-24

本轮已修复手机菜单点按区域偏小、据点长名册选中项不可见、手机界面保留桌面按键提示三类问题。未修改玩法、数值和玩家存档。以现有 iPhone 16 截图记录的 2556×1179 物理像素、安全区 `(177,0,2202,1116)` 为基准，当前实际游戏区域为 **364×240 逻辑像素，4 倍整数显示**。

## 修改依据与结果

| 问题 | 修改前依据 | 本次修改 | 验证结果 |
| --- | --- | --- | --- |
| 通用菜单行太密，点选容易落到相邻项 | 每行 16 逻辑像素；iPhone 16 的 3 倍 UIKit 像素密度下为约 21.3 pt | 仅手机改为每页 5 行、每行 34 逻辑像素；文字在各行内居中 | 约 45.3 pt 行高；终战 8 项菜单的末项“保存并返回主菜单”可通过触控轨道到达 |
| 通用菜单翻页点按区太小 | 原 16×18 逻辑像素，相当于约 21.3×24 pt | 手机翻页点按区扩大至 34×34；与选项区分离 | 约 45.3×45.3 pt；点击只翻页，不能误确认隐藏项，边框空白点击不选项 |
| 据点多页名册可能选中不可见角色 | 据点方向输入只更新 selected，不更新 scroll；原 10 行不容易暴露问题，手机 5 行会暴露 | 据点、战利品、通用菜单共用移动选择与滚动方法；绘制前保持选中行可见 | 8 人名册通过屏幕方向按钮遍历至末项；每次选中都处于当前页内 |

## 只读设备启动探针

为在不激活设备游戏界面的前提下读取真实布局，新增明确启动参数 `--phone-layout-probe`。仅该精确参数启用诊断；正常启动不运行。诊断在创建主游戏之前分支，不实例化 GameState、不创建旅程读取器、不读取或写入玩家记录、不播放音频、不处理操作输入。它仅测量原生视口、安全区与四类控制轨道，向 stdout 输出一次 JSON 后退出；不保存截图或诊断文件到设备。引擎自身缓存/日志不属于本脚本的记录访问。

[11 项探针隔离检查](layout-probe-checks.json)通过，涵盖默认关闭、近似参数拒绝、实际场景树不含游戏或音频节点，以及复用手机几何计算。测试夹具另行保存本地报告，发行探针只输出 stdout。设备若在后台被系统挂起或尚未给出有效安全区，应记录未采得，不以此触发前台启动。
