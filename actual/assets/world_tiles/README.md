# 世界地图瓦片 B · 朴素复古

采用用户选定的B画风，并按后续提供的《外传》世界图修正为**16×16原生格**。灰紫石材、橄榄绿山林、灰蓝海水与旧铜太阳符号，保持小尺寸地理符号的层次。此包是可复用资源，样图只用于验收拼接，不是最终39节点剧情地图。

## 交付资源

- `world-tiles.png`：原生PNG图集，512×656像素，32列。包括785格非占位图集单元；数量包含标准规则派生的边角，并非785张各自手绘的图片。
- `world-tiles.json`：ID、图集坐标、地形类型、8邻接掩码、道路连接、完整模块、来源边界与底层继承规则。
- `world-tiles.tres`：实际通过Godot 4.7.1保存并重新读取的TileSet，包含10组边/角匹配地形和自定义数据。
- `world-tiles.tsx`：Tiled图集定义；tile ID从0起，若TMX地图使用firstgid，需要在读写时进行相应换算。
- `modules/`：36个完整透明模块；由独立地形模块、连续山林组合与小尺寸地点符号构成，分别按16px边界写入图集。
- `sample-maps.json`：使用真实图集ID构成的样图，地形数据、地面/道路/组合层分开保存。

## 图集与拼接

海岸含草、雪、沙、盐四类；陆地过渡含森林、雪、沙、盐、沼泽、岩地六类。每类有47种有效8邻接组合，另含背景格。位值为N=1、E=2、S=4、W=8、NE=16、SE=32、SW=64、NW=128；只有相邻两个正交邻居都存在时才保留对应对角位。

海岸格自带海水背景。陆地过渡格是透明前景层，需要铺在草地等地面层上。山脉、森林、建筑使用完整多格组合；不可随机打乱组合内部格子。JSON的`modules[].tiles`已给出每格位置。完整组合的切开/重组经过像素一致性校验。

土路包含草、雪、沙、盐、岩五种地面上的16种四方向连接；海路和神宫通道使用独立叠加层，桥梁提供横/竖两种方向。桥、道路、模块的默认地形归属需要结合下述逻辑层处理，不从图案本身猜测通行能力。

## 地形数据边界

TileSet自定义数据为`terrain_id`、`terrain_key`、`tile_kind`和`route_mask`。此包的terrain_id是独立地理语义编号：草0、海1、沙2、雪3、盐4、沼泽5、森林6、岩7、石8、土9、木10、神宫石11。**它不等同于旧工程的战术类别编号。**

地点与装饰模块的terrain_id为-1，明确继承地图地面层；不因树冠、城堡、船或神殿图像覆盖一格就自动改为森林、墙或水。原生格是地图逻辑单位，整数放大仅影响显示。此包未改移动费用、回避、毒沼伤害、恢复格、战役解锁或原存档；战术瓦片与规则映射是后续工作，需要显式配置，不能直接把世界图编号送入旧战斗分类表。

## 来源与验证

基础材质及独立模块使用内置imagegen制作，源图和提示词保留在`../../source/world-tiles-b/`并隔离导入。此前偏近景的建筑稿保留为制作过程源图，运行符号使用重新按《外传》粒度制作的`world-symbols-generated.png`。四方向/八方向边角由标准掩码、选定材质和共享边界规则派生，没有将概念大图随意切成格子。

构建脚本：`../../tools/build_world_tiles.py`。Godot资源构建：`../../tools/build_world_tiles_resource.gd`。构建PNG后需要进行一次Godot headless导入，再构建tres资源。报告在`../../reports/world-tiles-b/`，包含逐图尺寸/字节数、共享边缘验证、模块还原验证、Godot资源和后台实际TileMap渲染。

使用最近邻采样、不启用mipmap，按1×/2×/3×/4×整数放大。图集紧密排列，因此线性过滤或分数缩放可能引入串色，不属于本包的显示规格。不会拉伸原图边角，也不会把完整图案用九宫格改变比例。

浏览`../../world-tiles/index.html`，或本机服务的`http://127.0.0.1:8765/world-tiles/`，可以切换图集/样图/转角检查、显示网格并点击查询ID与地形。图标、模块与图集的实际字节数见验收清单。
