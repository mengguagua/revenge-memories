# 《复仇与回忆》宣传官网

纯静态网页，无需安装依赖。默认英文，支持日文、简体中文；已选语言保存在此浏览器，下次打开会沿用。可以通过 `?lang=en`、`?lang=ja`、`?lang=zh` 直接访问。

在本目录运行：

```sh
python3 tools/serve.py --port 4173
```

访问 <http://localhost:4173>。`npm run dev` 等效。服务器支持视频的 HTTP Range，拖动进度无需从头下载；文字文件有 gzip 副本时自动提供压缩响应。修改源码后运行 `npm run optimize` 更新副本，浏览器刷新即可看到改动。

## 页面与交互

- 雪海像素首屏、剧情与双主角档案、三组玩法介绍、实机画廊、两段移动端视频、PC 与移动端说明、常见问题。
- 角色和玩法可切换。实机图与视频共用一个媒体窗口，前两项为视频，后续15项为PC截图及完整地图；支持横向缩略图带、前后切换和 Esc 关闭。
- 视频初始 `preload="none"`，没有 `src` 和 `autoplay`。切换封面不会请求视频；点击播放后才赋予地址并播放。关闭时暂停并释放媒体资源。
- 影院播放器提供暂停、进度拖动、静音、全屏、键盘快捷键；左右方向键切换媒体，聚焦进度条时方向键调整进度。遵守系统减少动态效果的偏好。
- 当前没有 Steam 商店链接，页面明确标注筹备中；未放置假的愿望单、购买或订阅按钮。
- 网站翻译与游戏语言支持分别说明，没有宣称游戏已提供三语言。英文 `Revenge & Memories`、日文 `復讐と記憶` 是本官网对中文名的译名，可在 `app.js` 与 `content.js` 集中调整。

## 素材来源与压缩

全部网站代码、图片、视频、原始截图、制作脚本和检查记录保存在本目录；不依赖 CDN、外部字体、分析服务或第三方视频平台。

- `source/captures/`：从当前 `actual` PC 游戏场景重新截取的九张原始画面，以及两张移动视频封面原始帧。使用开发流程检查点，保持角色属性与真实场景；只重定向临时保存位置，没有访问或修改玩家存档。
- PC 截图通过 Godot 实际 SubViewport 渲染，1278×720、426×240 逻辑尺寸三倍显示。启动前加载现有后台保护，禁止窗口显示和获取焦点。记录见 `source/captures/capture-report.json`。
- 运行素材在 `assets/images/`。PC 截图、雪海背景及角色头像采用逐像素一致的无损 WebP。头像和雪海直接复用游戏正在使用的素材，没有另画人物或伪造实机图。
- 两张视频封面保持原分辨率，用 WebP quality 92 优化，经实际显示检查文字、人物轮廓与像素边缘；原帧保留。未降低视频分辨率。
- 两段原片来自用户提供的 `first.mp4` 与 `fight.mp4`，运行副本分别为 `assets/video/journey.mp4` 与 `assets/video/battle.mp4`，约96.08秒和80.20秒。采用流复制、清理封装元信息与 faststart 优化，不重新编码视频或音频。
- 原片已是约1.2Mbps的H.264/AAC，因此严格无损优化仅各减少31字节，仍共29,305,633字节。没有把有损转码称为无损压缩；音视频流 SHA-256 完全相同，见 `reports/video-assets.json`。
- `reports/image-assets.json` 记录每张图用途来源、尺寸、字节数与压缩方式；当前网站使用41张图，合计2,838,208字节；39张逐像素无损，两张封面为视觉质量优化副本。三张后期世界图为212–236KB，保留896×1024原生细节以支持3倍查看，不为参考体积牺牲清晰度。

重新截图需要本机 Godot 与图形驱动权限：

```sh
bash tools/capture_pc.sh
python3 tools/prepare_assets.py
```

未修改游戏逻辑、打包游戏或安装／更新 iPhone。

## 验证与维护

```sh
npm run check
npm run optimize
```

静态检查覆盖三语键一致性、翻译引用、资源路径、PC截图安全区、视频默认不加载／播放及无损流校验记录。`tools/layout-audit.js` 提供可在浏览器中执行的只读文字容器安全区检查。

浏览器验收范围与交互结果见 `reports/browser-checks.json`；不把桌面浏览器的响应式检查称为手机真机测试。已部署到用户指定 VPS，正式地址为 https://revenge-web.gaocc.cc/；部署方式见 deploy/README.md。后续部署使用 `index.html`、`styles.css`、`app.js`、`content.js`、`robots.txt` 与 `assets/`；源码、原始截图和检查记录不需要上传。
