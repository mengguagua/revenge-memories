## 使用

打开上级 `index.html`。同目录的 `assets/`、`data.js` 和 `player.js` 一并保留，即可离线使用，无需安装 Node 或启动服务。

左右使用同一份无损 Godot 帧图集、同一时间索引。左边显示原动画，右边追加候选效果；水炮右侧另有上述灰青调色，候选不移除既有效果。这是局部增强方案的对照，不是全量替换方案。无声播放。

支持四组：普通剑击、背炮破坏、核心破坏、水炮命中。支持同步播放、循环、0.25/0.5/1倍速、拖动、上一/下一帧、特效时刻定位，以及原生1倍、近景2倍、完整手机布局。预览未提供写入游戏或确认接入按钮。

## 实际画面的来源

- 当前生产场景 `actual/scenes/phone.tscn`，调用原 `battle_animation.play()`、命中、部位破坏与受击控制器。
- 通过既有 `actual/tools/capture_campaign.sh`，在进程启动前加载防窗口、防激活保护；不弹出或聚焦游戏窗口。
- 1184×480手机布局，2倍整数像素；无损取得592×240逻辑画面。近景来自其中的256×240原生游戏区域。
- 在F21、F25已有检查点的内存副本中创建单次攻击。临时存档目录与玩家存档隔离。普通剑击22→17HP；水炮20→16HP、速度−1。
- 两种部件破坏样例将相应部件预先设为1耐久，沿真实命中规则破坏，保持本体生命。该条件在页面注明。
- 每个样例实际控制器均只调用一次命中结算。录制时间包含真实受击停顿、生命变化与回位，没有把其缩成素材循环。
- 记录的是Godot后台渲染、受控战斗样例，非iPhone真机录屏，也不是完整关卡自然试玩。

源帧与时间戳保存在 `captures/`；按60fps读取对应已捕获帧，并去重打包为无损PNG图集。不使用有损视频压缩或插帧。

## PixelFX来源与本次调整

上游 https://github.com/patch-gg/pixelfx ，固定提交 `a84159688af3ca37a4be05a0d422b94451b2e24e`（v0.3.0）。原始源码保留在 `pixelfx/`，遵循其中 LICENSE、NOTICE.md。未复制 Patch Pixel 字体。

`build_fx.mjs` 从原始 `hit-spark`、`zap-hit`、`water/splash` 派生预览模块。调整的是原生几何、粒子数量、速度、色阶和光强，不是把高清效果缩小或加像素滤镜。

| 预览 | 原生每帧 | 帧数 / fps | 适配 |
|---|---|---|---|
| 普通命中 | 72×56 | 31 / 60 | 米白、灰棕，短射线，6粒火花与3块碎屑 |
| 背炮破坏 | 72×56 | 31 / 60 | 旧黄铜色，绑定炮管断裂时刻 |
| 核心熄灭 | 72×64 | 55 / 60 | 灰紫放电；移除原来的横向入射电弧，避免暗示第二次攻击 |
| 水花 | 80×64 | 67 / 60 | 少量水滴、小水冠与短波纹；移除落石和二次向上水柱，减少光晕 |

背炮与核心对应既有破坏动作的第20帧，放电的内部0.05秒准备也作了对齐。命中与水花对应当前攻击的实际结算时间。候选不改变角色、武器、攻击次数、伤害、射程、减速、装备或核心规则。

完整变换记录：`fx-adaptations.json`。资源尺寸和字节数：上级 `asset-manifest.json`。原生、深浅底与界面安全范围检查：上级 `qa/`。
